# ParaBank - Testes Manuais Financeiros

### Resumo
Neste módulo, eu modelo testes manuais utilizando o [ParaBank](https://parabank.parasoft.com/), uma simulação de aplicação bancária criada pela Parasoft. O objetivo é demonstrar minha capacidade de testar regras de negócio estritas, lidar com cálculos financeiros e aplicar técnicas de Análise de Valor Limite (Boundary Value Analysis).

### Escopo de Testes
1. **Casos de Teste Tradicionais:** Criei o caso de teste `CT01_transferencia_fundos_pt.md` para mapear um fluxo feliz de transferência bancária entre contas do mesmo titular.
2. **BDD (Behavior-Driven Development):** Desenvolvi cenários em Gherkin (`.feature`) para explorar as validações de limite de saldo (ex: transferência de valor superior ao saldo disponível).

# ParaBank - Manual Financial Testing

### Summary
In this module, I model manual tests using [ParaBank](https://parabank.parasoft.com/), a banking application simulation created by Parasoft. The goal is to demonstrate my ability to test strict business rules, handle financial calculations, and apply Boundary Value Analysis techniques.

### Testing Scope
1. **Traditional Test Cases:** I created the test case `TC01_funds_transfer_en.md` to map a happy path of a bank transfer between accounts of the same holder.
2. **BDD (Behavior-Driven Development):** I developed Gherkin scenarios (`.feature`) to explore balance limit validations (e.g., transferring an amount greater than the available balance).

# ParaBank - Pruebas Manuales Financieras

### Resumen
En este módulo, modelo pruebas manuales utilizando [ParaBank](https://parabank.parasoft.com/), una simulación de aplicación bancaria creada por Parasoft. El objetivo es demostrar mi capacidad para probar reglas de negocio estrictas, manejar cálculos financieros y aplicar técnicas de Análisis de Valores Límite (Boundary Value Analysis).

### Alcance de las Pruebas
1. **Casos de Prueba Tradicionales:** Creé el caso de prueba `CP01_transferencia_fondos_es.md` para mapear un flujo feliz de transferencia bancaria entre cuentas del mismo titular.
2. **BDD (Behavior-Driven Development):** Desarrollé escenarios en Gherkin (`.feature`) para explorar las validaciones de límite de saldo (ej: transferencia de un monto superior al saldo disponible).
